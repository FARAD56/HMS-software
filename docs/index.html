Built for the people in the building

Each kind of account gets its own dashboard and only the actions that make sense for it.

Patients

  • See current medication with dose and duration
  • Track temperature and blood pressure over the last week
  • Find a doctor by speciality and book an open slot
  • Join consultations from a Google Meet link
  • Keep a personal to-do list with deadlines

Nurses and doctors

  • Book patients in with vitals and triage
  • Work from a patient list grouped by urgency
  • Record diagnoses, prescriptions and investigations
  • Set weekly consulting hours, in person or virtual
  • See hospital-wide diagnosis and demographic charts

Administrators

  • Manage every account in the Django admin
  • Promote an account to staff with one checkbox
  • Review and correct any clinical record

Follow-ups without the trip

When a patient books one of a doctor's slots, the system creates a Google Calendar event for the next time that slot comes round, invites both of them, and attaches a Google Meet link. The link shows up on both of their sessions pages.

  • Doctors publish weekly hours, in person or virtual
  • Booking signs in to Google once per session (Calendar events scope only)
  • Past appointments clear themselves from the list

Background

Part of an award-winning thesis

This is the care-management part of my undergraduate thesis in Computer Engineering at the University of Ghana, Enhancing Health Data Management, Synchronization, Visualization, Telemedicine and Medication Management. The thesis also covered a distributed database that keeps patient records in sync across hospitals and a medication-reminder service.

Run it yourself

Python 3.10+, then migrate, create an admin and start the server.

git clone https://github.com/FARAD56/HMS-software.git
cd HMS-software/HMS
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
